# annals 设计

> 跑在浏览器里的个人 AI 数据库。事件是唯一真理，状态由代码折叠，检索靠模型写的分档词袋走倒排。库里没有模型调用。

这是设计基线，代码以此为准，改设计先改这里。英文版在 [DESIGN.md](DESIGN.md)。

## 0. 定位

- **给谁用**：一个人，自己的数据，本地优先，零后端。第一个应用是 AI 角色扮演（AIRP，地狱难度），同一套原语也服务个人助手。
- **是什么**：三个原语的库。事件日志、折叠视图、稀疏索引。
- **不是什么**：不是 agent 框架，不是向量库，不是知识图谱。库里没有 prompt，不调模型，不知道什么叫"角色"和"债务"。这些全在上层应用。

## 1. 原则

1. **极简与低耦合，代码当做数据。** 凡是"现在如何"的问题，永远由系统直接告知模型，不让模型从历史记录里自己推导。
2. **事件与状态二分。** 模型擅长输出"事件"（append-only 的事实），不擅长维护"状态"（事件流向后推出来的结果：归属、位置、关系、债务）。状态必须由代码维护并每次注入。
3. **唯一真理是事件。** 消息、事件日志、角色卡、用户手工编辑是源数据。视图、索引、权重数值、向量全是衍生物，可随时由代码幂等重算。
4. **重活放到写入端。** 离线或异步做抽取、扩展、规范化。查询路径保持笨：运行时只有查表、加法、排序。
5. **硬信息走结构化通道。** 方向性和数值性的事实（谁欠谁、东西在哪、数额多少）会被注意力搅混，永远不委托给相似度检索或模型记忆。
6. **模型做分类，不做回归。** 让模型选档位，不让它打分；数值由代码的离散表映射。

## 2. 三个原语

### 2.1 事件日志 `EventLog`

```ts
interface AnnalsEvent<T extends string = string, P = unknown> {
  id: string;        // 调用方给或自动生成
  seq: number;       // 日志内单调递增，由日志分配
  at: number;        // 应用自己的钟：剧情 Day、存档时钟、墙钟都行。库永远不读 Date.now()
  type: T;           // 判别符："state.set"、"summary"、"bag"
  source?: string;   // 谁产生的：消息 id、导入批次。撤回 source 会删掉它产生的全部事件
  payload: P;
}
```

- `append` 追加，`retract(source)` 按来源撤回。用户 swipe、编辑、删除一条消息时，应用调一次 `retract(messageId)`，这条消息带来的状态、摘要、词袋一起消失，视图和索引重算。这是对模型输出不可知论的核心机制。
- `version` 每次变动加一，衍生视图拿它做缓存键。
- `toJSONL()` / `fromJSONL()` 就是导出格式。一个文件就是整个库，人眼能读，任何语言能解析，不依赖本库也能恢复。

### 2.2 折叠视图 `fold` / `latest`

视图是日志的纯函数，不存储，`version` 变了就再算一次。数据量小（单人几百到几千条），全量扫描亚秒级，不需要真的物化。

- `fold(events, reducer, init)`：任意归约。
- `latest(events, keyOf)`：每个键取最新一条。AIRP 的"物化视图"就是 `key = entity + attr` 的 `latest`。Map 的迭代顺序等于最近写入顺序，直接拿来做"活跃度"排序。

### 2.3 稀疏索引 `SparseIndex`

`term → (docId → tierCode)` 的倒排表，带反向表以支持删除。

- **只存档位，不存词频，不存文档长度。** 档位三档：`core` / `related` / `hint`，存成 1 / 2 / 3，一个 uint8。
- **分数 = Σ 命中词项 weight(tier) × idf(term)，再乘 boost(doc)。** 权重表、idf 开关、boost 全是查询端参数，改了不碰索引。
- **idf** 用 `log(1 + N/df)`，df 就是 posting list 长度，一行代码，不是 BM25。没有它，"猫"出现在每条摘要里就毫无区分度。
- **boost** 是应用注入的每文档乘数。库不知道时间，新近度衰减由应用用自己的钟算好传进来。
- `vocabulary()` 返回全部词项和文档频率。抽取 prompt 附带这个表，要求模型优先复用已有词项，让词表收敛到个人语言。
- `serialize()` / `deserialize()` 存 Dexie 或别处；或者启动时从词袋事件 `rebuild()`，数据量小，亚秒级。

## 3. 分词：写入端和查询端必须同一个函数

词袋是模型写的，会出"小鱼干""债务"这类多字词；查询是用户原话。两边词表对不上，倒排就是空的。

`Intl.Segmenter` 把"小鱼干"切成"小 / 鱼 / 干"三个单字（Node 22 ICU 实测），所以：

- **规范化**：NFKC（全角转半角、兼容字形）+ 小写。
- **词**：`Intl.Segmenter`（word 粒度）有就用，没有退化成按文字系统切分。
- **CJK 二元组**：对每段连续 CJK 永远生成，不依赖分词器的判断。"小鱼"、"鱼干"是让查询"鱼干"遇到词袋词"小鱼干"的唯一桥。
- **停用词**：一个小表，可替换。模型写的词袋里几乎没有这些词，用户的问题里全是。
- **写入端展开**：`add` 时把每个词袋词再过一遍分词器，子词以同一档位入索引（`expandTerms`，默认开）。同一词在两档里出现取强的那档。

繁简统一暂不做，需要一张映射表，等真遇到再加。

## 4. 源数据与衍生物的边界

线划在这里：**需要模型才能再生的，都是源数据；纯代码能再生的，才是衍生物。**

| 源数据（导出） | 衍生物（不导出） |
|---|---|
| 消息原文 | 倒排索引 |
| 事件日志（状态变更、摘要、词袋档位） | 折叠视图 |
| 角色卡、世界设定 | 档位映射后的权重数值 |
| 用户手工编辑、配置 | 向量 |

由此有两个不同的函数，不能混成一个：

- **`rebuild()`**：从事件日志重放到视图、重建索引。纯代码，幂等，免费，导入和修复之后随手按。
- **`reextract()`**：用新 prompt 或新模型重跑抽取，产出新的摘要和词袋事件。烧 API 额度，不确定。模型升级时才按。

摘要和词袋虽然是模型产物，但它们是事件，带 `source`，随消息一起回滚。

## 5. 存储

- 存储是适配器：`EventStore`（事件）和 `BlobStore`（可丢的衍生 blob）。
- 库自带内存实现，测试在 Node 里跑，不开浏览器。
- Dexie / IndexedDB 适配器是单独入口，以后 SQLite 也一样，核心永远零依赖。
- 浏览器侧启动时应用调 `navigator.storage.persist()`。图片存 Blob，不 base64。

## 6. 应用画像：AIRP 怎么用这三个原语

这一节是应用层的约定，不是库的一部分。写在这里是因为它是第一个用户，也是最难的那个。

### 6.1 时间

- 双轨：每条事件记 `day`（从剧情起点算的整数）和 `storyDate`（剧情内日期，ISO `YYYY-MM-DD`，用于季节、节日、生日）。`at` 用 `day`。
- 系统侧算好注入："Day 128（2027-03-14，早春），距上次约会 6 天，距他生日 11 天"。不让模型做日期算术。
- "三个月后"这类跳跃单独记一条事件，不让剧情产生暗箱跨度。
- 查询里的相对时间（"昨天"、"上周"）由应用解析成 `at` 区间，作为过滤或 boost 条件。词袋里不可能有"昨天"。

### 6.2 状态系统

- 事件类型 `state.set`，payload `{ entity, attr, value, valueKind? }`。`oldVal` 不让模型填，代码从当前视图取，相同就丢。
- 属性白名单：位置、归属、生死、关系、债务、未兑现的承诺、不可逆的描述。不记流水账。
- 有向关系用显式方向字段，注入时渲染成主宾分明的规范句："char 欠 user 49.5r（Day 3 红包误发，未结清）"。禁止无方向的自由文本。
- 允许模糊值："猫 | 归属：未明确（user 捡到，角色尚未同意养）"。剧情没定的事实不硬塞。
- 活跃度淘汰：实体超过 N 条事件未被提及移出注入块（不按剧情天数，一句"三个月后"会清空所有实体）。再次被检索命中则重新挂载。
- 注入的状态块目标 < 150 token。前端有面板，自动维护 + 手动覆写，用户是最高权限。

### 6.3 抽取流水线（唯一允许模型写库的通道）

- 独立异步调用，与 RP 主调用分离。低温度，强 JSON，附带最近 N 条对话。禁止在 RP 主调用里捎带抽取任务。
- 一次产出三件套：场景摘要、状态 patch 数组、词袋三档。三者都是冷静的提取任务，合并一次调用。
- 词袋规范：词项 ≤ 15，core ≤ 3；禁止自由数值；prompt 附带 `vocabulary()`，要求优先复用。
- 代码侧：schema 校验，失败重试，全部事件带 `source = 消息 id`。
- 节流：每 N 条消息或场景切换触发。初版同步等待，异步队列是后期优化。
- 摘要分层：消息 → 场景摘要 → 章节摘要，每层保留 Day 锚点、关系转折、未兑现承诺。一条摘要覆盖多条消息，`source` 挂多个消息 id 的话，任一被撤回即整窗重抽。

### 6.4 提示词组装

```
[角色卡 + 系统设定]   ← 缓存
[章节摘要]            ← 缓存
[状态块]
[检索召回片段]
[近期消息]
```

检索在发请求前由代码完成，毫秒级，每条消息都带，没有额外模型调用。易变内容只进最后一条用户消息，稳定前缀用 `cache_control`。

## 7. 路线图

- **v0.1 原语**：`EventLog`、`fold` / `latest`、`SparseIndex`、分词器、内存存储、JSONL 导入导出。已完成。
- **v0.2 适配器**：`annals/dexie` 的 `EventStore` / `BlobStore`；`rebuildIndex()`、`bagFromText()`、`parseBag()`；`annals/airp` 的状态 patch 合同、视图、状态块渲染。已完成。
- **v0.3 AIRP 画像**：状态事件约定、状态块渲染、相对时间解析，作为独立入口或示例，接入 pocketverse 替换 MiniSearch 与 `state_update`。
- **v1 语义点亮**：词袋抽取接入流水线，三档映射配置，查询日志。
- **v2（暂缓）**：信息不对称（场景"在场者"标签 + 各角色 knows 清单，进阶为按角色视角过滤上下文）、RRF 混合检索、本地 dense embedding、查询日志调优。

## 8. 验收案例（真实踩坑回归）

1. **锚位游离**：剧情从客栈 A → 夜市 → 睡醒在客栈 B 后继续对话 20+ 条，角色不得再落脚在 A。状态块应显示"当前：客栈 B"。
2. **红包方向逆转**：user 发 50r → char 退 0.5r 后，任意后续表述必须是"char 欠 user 49.5r"，不得翻转。swipe 撤回退款消息后状态自动回滚。
3. **语义穿透**：写入"昨天半夜猫偷吃了大案板上切的 50 块小鱼干"，查询"黑炭昨天晚上吃了什么"必须命中（依赖词袋里的别名"黑炭"和二元组"鱼干"）。
4. **回滚一致性**：编辑或删除某条消息后，其 `source` 挂靠的事件与词袋全部消失，视图与索引重算后一致。
5. **备份往返**：全量导出 → 清空库 → 导入 → `rebuild()` 后，以上行为全部不变。

2、4、5 已在单测里；1、3 的检索部分已在单测里，状态块部分等 v0.3。

## 9. 非目标

- 知识图谱、图可视化、实体消歧。写入端的"重活"会重到单人用户养不起。
- SPLADE 之类需要专门编码器的稀疏模型；微调。
- 多端同步。只有导出文件做纯单机备份。
- 群聊多角色（v2 的信息不对称是单角色视角过滤，不是群聊）。
